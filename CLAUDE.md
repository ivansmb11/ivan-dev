This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

Personal developer portfolio site built with Nuxt 4 + Tailwind CSS v4, prerendered to static HTML and deployed to Firebase Hosting.

## Commands

```bash
npm run dev        # Nuxt dev server (Node 24, see .nvmrc)
npm run build      # nuxt generate: static site in .output/public
npm run preview    # Serve the generated site on port 4173
npm run assets:sync  # Upload app/assets and public/ icons to Supabase, rewrite app/assets/bucket.json (needs SUPABASE_SERVICE_ROLE_KEY)
```

`esbuild` is a direct devDependency only so npm can place the version Vite 8 needs; without it `npm install` fails with ERESOLVE.

## Architecture

- **Nuxt 4** (Vue 3.5, `<script setup>`), file-based routes in `app/pages/`, path alias `@` / `~` → `./app`
- Prerendered with `nuxt generate` (`ssr: true`, no server at runtime). Firebase serves `.output/public` with `cleanUrls`; unknown paths get Nuxt's `404.html`, whose catch-all page redirects home
- **Tailwind CSS v4** via the `@tailwindcss/vite` plugin in `nuxt.config.ts`
- **@vueuse/motion** (`@vueuse/motion/nuxt`) for `v-motion`; initial styles are rendered on the server
- **@nuxtjs/i18n** for English/Spanish, `no_prefix` strategy: one URL per page, English prerendered, `app.vue` switches to the saved or browser language after hydration
- **Lucide Vue Next** for icons
- Font: Inter (variable, `opsz` axis) via Google Fonts; large sizes switch to the display cut automatically
- Nuxt and module composables (`useI18n`, `useRouter`, `useRoute`, `useState`, `useHead`) are auto-imported; everything else, including our own components, is imported explicitly

### Rendering rules

Every component also runs on the server during `nuxt generate`, where `window`, `document` and storage don't exist.
- Read browser state (`localStorage`, `sessionStorage`, `matchMedia`, scroll) only in `onMounted` or event handlers, never in `setup`.
- The first client render must match the prerendered HTML: start from the server's value and correct it in `onMounted` (see `booted` / `hydrated` in `app.vue` and `useTheme().sync()`).
- Anything that must apply before paint (saved theme, intro already seen, old `/#/` links) lives in the inline `beforePaint` script in `nuxt.config.ts`.

### Design System

Visual source of truth: a Framer "Personal Portfolio" reference (orange hero, off-white paper, heavy uppercase display type, gray chips with a red-orange asterisk).
- Tokens live in `app/assets/css/main.css` `@theme`: `paper`, `card`, `mist`, `mist-soft`, `line`, `muted`, `graphite`, `ink` (neutrals), `onyx` (fixed near-black), `ember-deep` / `ember` / `ember-bright` (hero and footer orange), `accent` / `accent-deep`, `night`. Display sizes: `text-display-hero|xl|lg|md`. Utilities: `container-site`, `link-underline`, `placeholder-hatch`.
- Light is the default. Dark mode is opt-in (navbar toggle, menu, `D` key): `html.dark` overrides only the neutral tokens. To stay dark-safe, use `bg-card` (not `bg-white`) for raised surfaces, `text-paper` on `bg-ink`, and fixed colors (`text-white`, `bg-onyx`, `text-onyx`) only on the orange hero/footer, photos and `bg-night`. No `theme === 'dark'` branches in components.
- Images are served from the public `assets` bucket of the Supabase project `ivan-dev` (`ctqzhlionfyyhujzzped`), not bundled. `app/assets/bucket.json` lists what's in the bucket; `slotSrc(id)` and `assetUrl(path)` in `app/assets/slots.js` turn it into URLs. After adding or replacing an image (locally in `app/assets/` or straight in the bucket), run `npm run assets:sync` and commit `bucket.json`.
- Layout images go through `AssetSlot` with an id from `app/assets/slots.js`. Until `images/<id>.<ext>` is in the bucket it renders a labeled placeholder. Vibebify's screenshots and diagram logos use `assetUrl('vibebify/…')` / `assetUrl('logos/…')`. Favicons live under `meta/` in the bucket (copies stay in `public/` for `/favicon.ico`).

### Animations

Use `v-motion="reveal(delay)"` for scroll reveals and `v-motion="enter(delay)"` above the fold (`app/motion.js`); both turn off under `prefers-reduced-motion`.

## Content Sync Rules (CRITICAL)

When updating portfolio content, **ALL** of the following must be kept in sync:

| Source | What it contains |
|--------|-----------------|
| `i18n/locales/en.js` | English text for all sections |
| `i18n/locales/es.js` | Spanish text for all sections (must mirror en.js structure) |
| `app/pages/agents.vue` | Hardcoded plain-text version of all content for AI agents/crawlers |
| `nuxt.config.ts` | Page `<title>` and `<meta name="description">` (`app.head`) |

Additionally, some content is hardcoded in Vue components (not i18n):
- `app/components/TechTicker.vue`: tech list array
- `app/components/AboutSection.vue`: stats counter values (years, companies, projects, technologies)
- `app/components/AchievementsSection.vue`: achievement entries array (URLs, credentials, logo slot ids)
- `app/components/CareerSection.vue`: job entries array (image slot ids)
- `app/components/PortfolioSection.vue`: project entries (tags, GitHub and case-study links)
- `app/components/TrustedSection.vue`: logo strip entries

**Never update content in only one place.** Always check all locations above.

## Style Rules

- Never use em dashes (—) in any user-facing text. Use commas or pipes instead.

## Deployment

Firebase Hosting (project: `ivan-d3277`). GitHub Actions auto-deploy on push to master and on PRs. Build output goes to `.output/public` (`nuxt generate`). CI uses the Node version in `.nvmrc`. `public/sitemap.xml` lists the routes by hand; add new pages there and to `nitro.prerender.routes`.
